# 2026-10-29：单入口通信修复与真实数据复验

## 已复现的通信故障

当前Windows的127.0.0.1:8765由VS Code转发到Linux控制入口。测评列表能加载，但选择后返回Linux上的23966等独立端口，Windows未转发这些端口，因而无法打开。这是客户端可达性问题，不能用服务器HTTP200证明正常。

## 修复

- 每次测评仍分配独立空闲回环端口；检查连接与实际bind，被占用则换候选，绑定竞争失败则重试，不抢占其他服务。Windows探测使用独占绑定，服务不允许复用正在占用的地址。
- 同时返回独立地址 `/evaluations/<evaluation-id>/`。浏览器优先校验独立端口；不可达或身份不符时，校验同入口下的独立地址再跳转。因此只转发一个总入口也能选择多个测评。
- 独立地址只代理本项目已登记、正在运行的测评监听器，不能指定任意主机或端口。路径下的任务、图像、地图、视频、刷新和SSE均由该测评处理。静态资源共用不合并任务数据。
- 自动打开时优先选择已有步骤且没有采集错误的Episode。无数据/采集异常任务仍保留，明确显示异常，不再默认进入空画面。
- SSE随监听器关闭退出，避免连接清理后继续访问已关闭的存储。

## 未能声称通过的实时采集项

只读核对最近已接入批次的supervisor记录，发现它们已退出，包含退出码-15、0和automatic_restart_allowed=false；另一运行名称明确为no-visualization。部分索引记录带有生产端写入的Capture incomplete错误。当前未找到仍在持续追加导航事件的已接入模型进程。

因此，本轮不能声称已观察到“新测评自然出现、实际新动作/图像持续到达、真实结束事件实时转态”全部通过。没有为补齐验收重跑模型，没有重新发送旧数据冒充实时事件，也没有改写科学结果。已向用户询问当前在跑的目录，取得该事实后才能继续只读观察对应真实事件。

环境BEV底图的生成/完整性不由上述步号同步证明；缺少地图数据时仍须明确缺失。CPU合成延迟测试也不作为本轮真实运行延迟证明。

## 使用

已有旧页面需要一次重新载入以加载更新后的JavaScript；不需要重新启动测评。在8765等已转发入口点击选择，测评页面可使用同一入口下的 `/evaluations/<id>/` 地址。该路径在任何系统使用相同逻辑，不依赖本机特定目录、模型名或数据集名。
