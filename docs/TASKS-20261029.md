# 2026-10-29：最新测评发现与按任务聚合

本记录取代此前“按数据源/分片分别展示入口”的层级定义。**一项完整测评任务对应一张选择卡片、一个端口和一个地址；分片只是内部数据源。** Episode和数据集在该任务页面内查看，不为每个分片额外生成用户入口。

## 修复的两个问题

最新的full3062任务没有SDK索引条目，原始记录使用 `trace/episodes/<id>/trace.jsonl`。旧适配器只识别 `shards/shard-*/attempt-*/episodes/*/trace.jsonl`，因此漏掉了原本已经保存的真实轨迹。现在两种primitive-event布局都支持，Episode内相对图像路径也会安全解析，原始文件不重写、不重跑模型。

此前同一天SDK测评只有日期，旧条目可能排在前面；完整历史扫描也可能拖住新条目。现在按真实开始时间排序，新发现的记录先发布；快速检查已知任务目录及新子源，任务的新增分片和完成计数不必等待整个历史目录遍历。手动刷新可要求立即检查，发现错误会显式报告。

## 任务身份与通用接入

当前控制器的同一父目录有scope-manifest.json及job-registry.json，因此被识别为一项任务。规则不包含full3062、AwareVLN或数据集名称。

任何模型也可在完整测评的输出目录放置标准声明文件：

```text
outputs/my-evaluation/
  process-show-task.json
  worker-a/       # SDK/标准JSONL/受支持primitive trace数据源
  worker-b/
```

```json
{"id":"my-evaluation-001","name":"MyModel evaluation","expected":1000}
```

声明目录下的来源聚合为同一任务；任务ID独立于分片数量，新来源加入时沿用任务端口。没有多来源目录时，SDK使用整个测评一致的run_id、每个worker正确的attempt/episode身份即可。未知私有记录格式仍需要适配器。

数据隔离以逻辑任务为界。一个任务可同时包含R2R/RxR等多个数据集，页面内筛选不会更换任务地址；其他任务的数据读取被拒绝。分片名称和同步详情保留在内部信息中。旧的分片监听器不再恢复成独立任务端口；同入口下的旧分片路径会引导到其所属任务。
