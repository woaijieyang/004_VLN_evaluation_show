# process-show：本目录测评可视化

2026-10-29 更新：每次测评按唯一身份分配独立端口。总入口只供选择，不再显示全部测评混合任务；SDK/适配器直接写入的测评也能单独选择。同名运行按来源目录和模型区分。

本轮96项测试、现有6组测评分端口及合成采集延迟的实际结果见 [隔离与更新验收](ISOLATION-20261029.md)；下文早期验收记录保留原日期和范围。

用于查看本机当前项目中的 VLN 测评：真实视角、场景 BEV、instruction、实际动作与执行步数同步回放，并可保存完整 MP4。

**三个系统入口做同一件事：打开本机的测评选择页。无需 EXE，无需 SSH，也不需要 Windows/macOS 到 Linux 的映射。**

源码仓库：[woaijieyang/004_VLN_evaluation_show](https://github.com/woaijieyang/004_VLN_evaluation_show)。

将仓库下载/克隆为目标模型项目内的 `process-show` 文件夹，然后运行对应入口。例如在已有项目目录中：

```bash
git clone https://github.com/woaijieyang/004_VLN_evaluation_show.git process-show
```

仓库不包含部署主机的 `service.json`、`sources.json`、连接凭据、模型数据或缓存。首次运行入口会在 `config/` 自动生成当前机器、当前父目录的配置；无需填写服务器地址。字段示例见 `config/*.example.json`，不要把示例当成已绑定的服务配置。

## 1. 启动与停止

| 系统 | 总目录中的入口 | 使用方式 |
|---|---|---|
| Linux | `process-show-linux.sh` | 终端运行；有桌面时自动打开浏览器，无桌面时打印本机地址 |
| macOS | `process-show-macos.command` | 双击或在终端运行，自动打开本机浏览器 |
| Windows | `process-show-windows.cmd` | 双击，或把文件拖入 CMD 后回车；无需 Bash |

入口不依赖终端当前工作目录。它根据自身所在位置找到插件与项目根目录。

启动后出现选择页，可在弹窗中搜索测评。选择后进入对应测评的独立端口。终端菜单可重新打开选择页、停止本目录服务、查看状态和准备依赖。退出菜单或关闭终端不会停止已启动的后台回放；需要停止时使用菜单或页面按钮。

Linux 示例（当前部署）：

```bash
/data/zy/vln/case1/process-show/process-show-linux.sh
```

也支持 `start`（打开选择页）、`stop`、`status`、`list`（JSON目录）和 `select`（终端编号选择）。不要把 Markdown 星号 `**` 复制进命令。VS Code 远程文件树双击脚本只会打开编辑器，不会执行。

## 2. “只在当前目录有效”是什么意思

以插件父目录作为最终根目录。例如：

```text
/data/zy/vln/case1/                ← 最终根目录
  process-show/                   ← 插件
  outputs/eval-a/                  ← 可识别
  experiments/model-b/eval-b/     ← 可识别
/data/zy/vln/other-project/        ← 不在作用范围内
```

选择弹窗会显示实际作用根目录。所有运行发现、步骤、图片、地图、缓存、下载、停止操作都受该目录边界约束；拒绝符号链接/Windows重解析点逃逸。不遍历全盘，不注册全局服务、全局命令、全局映射或开机任务。模型、数据集、环境、源码和历史备份目录不作为可视化运行目录扫描。

插件复制到新项目后，入口只为新的父目录建立本地配置，并清除指向外部项目的旧监听源；不会沿用旧项目的数据连接。

## 3. 选择哪一次测评

弹窗按运行展示：

- 日期与时间（Asia/Singapore）；
- 模型概况及可用的权重摘要；
- 数据集、已完成条数 / 已知总数；
- 来源记录的运行状态、缓存期限与保留状态；
- 完整运行名称，避免同一天不同模型混淆。

状态为“运行中（进度记录）”表示来自测评 progress 文件，不代表插件独立检查了模型进程。总任务数缺失时显示未知，不用最大步数或猜测补齐。

可以识别本目录内带 manifest/trace 的受支持运行，以及通过通用 SDK 采集到索引中的记录。只有成绩 JSON、没有观测/动作信息的目录不能恢复完整回放，不能把它伪装成可视化数据。其他模型可接入 [SDK/API](API.md) 或实现自己的适配器。

通用接入不依赖模型名称或数据集名称，支持两条路径：

1. **Python SDK**：任意模型在reset/动作返回后调用 `Recorder.record_step`，插件从索引发现测评，包括设置了自定义 `source_run` 的适配器记录。
2. **版本化 JSONL**：按 [API](API.md) 的start/step/end格式，每个Episode一个UTF-8 `.jsonl` 文件，放在项目内独立输入目录即可被发现，不要求Case1的shards布局或manifest。第一条完整记录必须是schema_version=1的start，带模型、run、数据集、场景和指令等元数据；同一目录可含多个模型/运行，插件按身份分组并分别分配端口。非Python模型也可写这个协议。

通用性不等于猜测任意框架的私有输出格式。未遵循接口的输出需要适配器；原始成绩、缺图、缺位姿等能力按实际缺失展示。插件不会为了“显示正常”补造图像、位置或完成结果。

扫描异步进行；已有目录缓存先显示，随后更新完成条数。过期且没有保留内容的测评从列表自动剔除；正在采集的内容和保留样本不提前清除。剔除只影响可选回放，原始测评数据不会删除。

## 4. 不同测评使用不同端口

选择页使用本目录自己的控制端口。每次测评分配一个独立的本机回环端口，地址形如 `http://127.0.0.1:28498/`，实际端口以返回地址为准。

- 绑定前检查端口空闲；被其他程序占用时跳过，不抢占、不结束别的程序。
- 同一个有效测评重复打开复用已有端口；不同测评端口不同。
- 测评端口只返回该测评的任务；不能用其接口读取或固定另一测评的任务。
- 停止某个测评端口不会停止另一个测评，更不会停止模型。
- 端口记录仅保存在本目录 `outputs/process-show/run-sessions.json`，不创建全局注册表。
- 服务重启会恢复仍有效的测评端口；过期且无保留内容的端口会被回收。

这里的“映射”是 **当前根目录内的测评身份 → 原始记录/索引 → 独立回放端口**，与跨系统远程连接无关。

测评身份不使用显示名称代替：页面以所在端口的 `evaluation_id` 为准；来源目录、run与模型相同的一次测评内切换Episode。相同run名称、相同模型但位于不同来源目录的测评也分开。选择弹窗显示来源目录与阶段，同名旧链接无法唯一匹配时要求重新选择，不展示混合列表。总入口未选择前任务数为0。

各测评端口的任务、刷新/补载、同步详情与实时通知只跟踪本次测评；另一个页面选择测评不会覆盖当前页的身份。目录级缓存/保留规则仍按已约定的“每数据集合计”执行。

## 5. 回放与 BEV

选择 Episode 后，拖动以实际执行 step 为单位的进度条，或点击横向动作序列。第0步是 reset；一次模型调用可能执行多个动作，调用数与步数分别显示。

RGB、BEV、动作和计数按同一步提交更新。图片未准备好时，两幅图保留此前一致的步骤。指令可展开和复制。

BEV包含已提供/已核验的真实环境地图，并叠加起点、目标、轨迹和当前位置。默认只跟随中心，不自动放大；用＋/−或滚轮手动缩放，支持全局路线。中间位置使用小点，图内不标步数。

Case1可选适配器从真实GLB生成CPU切顶俯视图，核验与navmesh的对齐；部分压缩纹理采用几何高度着色。通用模型可直接提供BEV图和坐标变换。没有场景资产时明确提示缺少底图，不从路线猜墙体。冷地图生成显示排队状态，支持独立重试；不使用测评GPU重建画面。

“第X步未保存图片，显示第Y步画面”表示原记录缺少X步图片，使用此前最近的真实图片；BEV仍是X步位置。勾选“只看当前步原始帧”可关闭回退。刷新不能恢复原本未采集的图片。

## 6. 保存位置与缓存

点击“保存到…”：

1. **保留在运行目录**：固定到本项目 `outputs/process-show`，免于缓存到期自动清除。
2. **保存到本机**：下载完整MP4；浏览器支持时弹出“另存为”选择目录。内嵌浏览器不支持目录选择时使用标准下载，并提示从下载列表查看位置。

本机路径由浏览器选择，不传给服务器；本机下载不会改变运行目录保留策略。尚未完成编码的视频需先等待生成。

缓存默认 **1小时**，在“保留设置”中可选15分钟、30分钟、1/3/6/24小时，或自定义 **1分钟至30天**。视频以编码完成原子提交为计时起点，采集和编码中的任务不提前清除。测评选择列表根据结束/最近进度记录时间与缓存规则过滤，固定/保留样本可继续访问。

默认每数据集跨测评合计保留5条。侧栏展开“保留轨迹”可填写Episode ID：少于5条随机补足，超过5条全部保留；相同ID不同run/attempt都会匹配，只想固定某次运行时用该任务的“☆保留”。清空输入并保存恢复抽样，不会取消手动固定。

缩短缓存时间会影响尚存未保留视频，可能在下次清理时到期；已删除视频不能恢复。清理每分钟执行，仅处理插件登记的派生文件，下载期间有租约保护。存储不足时暂停新增处理，不提前删除受保护内容。

## 7. 刷新

侧栏“刷新 / 补载历史”重新检查本目录已接入的记录并重试当前画面；详细状态在弹窗。支持5/15/30秒检查间隔、清空筛选和加载更多任务。

增量导入有持久化游标，重复刷新不重复导入；半行JSON等待后续追加，错误可见并可重试。历史未同步完整时明确显示已载入/原记录步数。MP4独立编码，不阻塞网页已有步骤回放。

已有活跃trace每0.5秒检查追加，全目录新任务发现另行扫描。SDK先保存压缩观测和步骤，再由独立编码流程生成完整画面，避免采集队列逐步合成1920×1080画面。SSE按本次测评的完整记录修订发通知，不再用全库最大更新时间猜测变化。选择弹窗每5秒更新一次已发现测评。

刷新详情显示当前测评最近索引更新时间、采集/处理错误和停更时长。SDK记录没有终止消息时，不能据此认定模型仍运行或已完成；停更时明确提示源进程状态未知。已丢失的观测和终止事件不能靠刷新补造。采集端应在每次环境动作后调用 `record_step`，退出前调用 `end_episode` 和 `close`；旧的常驻采集进程需在下一次正常启动时加载新版SDK，不会热改正在运行的模型。

## 9. 初次使用与接入

需要Python 3（实际验证为Linux 3.10、Windows 3.13）。首次启动缺少Pillow/FFmpeg依赖时，入口在本插件 `.venv/` 准备锁定依赖，不修改系统或模型环境；首次安装需要联网。菜单4可重新准备依赖。

SDK示例见 [examples/record.py](../examples/record.py)。`from process_show import Recorder` 与旧公开模块导入继续有效。通用JSONL供非Python模型使用。只读接入已有输出；完整逐步图片需要下次新运行主动采集。未接入的模型不能仅凭成绩恢复画面。

新测评可从 `python process-show/tools/evaluate.py 本目录测评脚本.py [原参数]` 启动。Case1下一轮补丁仍在 `integrations/`，没有热改当前冻结测评。

## 10. 验证与限制

[验证记录](VALIDATION.md) 区分单元回归、真实已有输出和合成工程测试。Windows本机已实际完成隔离项目启动、弹窗目录接口、测评选择、MP4生成/读取、停止与重启；没有依赖Linux来完成这项测试。Linux已有测评已验证独立端口与数据过滤。macOS目前通过共用逻辑和分支测试、入口语法检查，**没有实际Mac设备的运行验收**。

当前聊天中已有的远端页面连接仍保留兼容桥，属于历史调试访问方式；三个新入口均不调用SSH或跨系统映射。没有新增模型调用、模拟器导航或测评GPU任务。

### 防止打开错误机器上的端口

选择器在跳转前探测目标健康接口，并校验同一根目录与测评身份；失败时留在弹窗显示原因。Linux无桌面环境打印的是**服务所在Linux主机**的本机地址，不能直接当作另一台Windows电脑的localhost地址。当前会话的旧调试访问桥会处理自身的各测评入口，但三个正式入口没有跨系统连接依赖。

本轮最终自动回归：Linux85项（1项平台跳过）、Windows85项（3项平台跳过）。具体证据、跳过解释和未实机验证项见 [验证记录](VALIDATION.md)。可用 `--no-browser` 在不打开窗口的情况下执行命令行检查。

### 命令行完整流程复验（2026-10-25）

正式启动入口支持 `start --no-browser`；终端编号选择支持 `select --no-browser`。选定测评后应访问接口实际返回的 URL，不能根据运行名称或固定端口自行拼地址。入口打印的 `127.0.0.1` 属于**运行服务的机器**；远程 Linux 输出的地址不等于 Windows 已具备该端口。

本次除 Linux 入口和服务端检查外，还从 Windows 客户端经现有调试入口实际执行了“选择测评 → 读取返回页面 → 读取脚本 → 健康身份/CORS校验 → 读取任务”。R2R 的28498、RxR的33693均返回HTTP200，且测评身份与选择项相符。Windows原生CMD也在全新隔离项目中启动、发现两次合成测评、通过API和终端编号选择，访问各自独立端口，并验证停止后子端口关闭。合成记录仅验证工程流程，不代表模型导航结果。

可重复运行的检查脚本（从目标模型项目根目录运行，使用已准备好依赖的Python）：

```bash
# 针对本机已有两次测评的选择页；端口替换为本机入口实际打印值
python -B process-show/tools/maintenance/verify_entry_flow.py --control http://127.0.0.1:控制端口 --output outputs/process-show/entry-flow.json

# Windows原生入口隔离验收；不会打开浏览器或停止已有服务
python -B process-show/tools/maintenance/verify_entry_flow.py --fixture-entry --output outputs/process-show/entry-fixture.json

# 全套Python回归；首次使用须先通过入口生成当前目录配置
python -B -m unittest discover -s process-show/tests -v
```

首个检查要求至少两次可访问的测评；如果列表不足，明确失败，不用空列表代替通过。脚本将回环请求直接发往本机，绕过HTTP代理，检查不同端口、相同scope与测评ID、重复选择复用和跨测评读取拒绝。未准备中文字库的Linux可运行 `python process-show/tools/maintenance/bootstrap_font.py`，下载经SHA256校验的Noto字体到插件自己的 `.assets/`；可用 `PROCESS_SHOW_FONT` 指定本机已有字体。

公开发布包含通用代码、测试、可选Case1接入补丁和少量复验工具；部署历史迁移脚本、旧EXE/入口、主机配置及运行证据不纳入发布。`tools/legacy/` 中保留旧协议测试所需兼容源码，三个正式入口均不调用它们。当前桌面调试桥不作为产品安装依赖。Mac实机、浏览器实际点击/保存对话框和整机断网测试仍未在本轮重新验收。
